면담 대상   : 결제플랫폼팀 정 매니저, 정산팀 김 책임, 재무팀 박 차장, ADTech플랫폼팀 이 책임
일시        : 2026-04-22
대상 프로세스: 미리보기·코인 결제 매출 (B2C) — Order-to-Cash for a content platform

────────────────────────────────────────────────────────
※ 본 프로세스는 "결제 시점"과 "매출 인식 시점"이 다른 전형적인 플랫폼형 매출이다.
   결제 → 가상재화(쿠키) 충전 → 회차 잠금해제(소비) → 정산 → ERP 전기까지 4단계의
   인터페이스가 끼어 있어 IT감사 관점에서 인터페이스 완전성과 정산 계산 정확성이 핵심이다.
────────────────────────────────────────────────────────

▣ 1단계 — 사건 흐름 (Events)

  사건 1) 유저가 모바일 앱에서 "쿠키 충전" 버튼을 눌러 결제 요청 (Front-end).
  사건 2) 외부 PG사(KCP / 토스페이먼츠 / Apple IAP / Google IAP)에서 결제 승인 완료 후
          웹훅(callback)으로 결제 결과를 통보 (Back-end가 수신).
  사건 3) Back-end가 COOKIE_LEDGER 테이블에 쿠키 잔액을 +N 적립.
          이 시점의 분개: 차) 현금/PG미수금  대) 선수금(이연수익)
  사건 4) 유저가 회차를 잠금해제 → COOKIE_LEDGER에서 -1 차감 + EPISODE_UNLOCK 기록 생성.
          이 시점의 분개: 차) 선수금  대) 매출(수익 인식)
  사건 5) 정산 시스템이 일/월 단위로 작가 RS(Revenue Share)와 플랫폼 수수료(Net Revenue)를
          계산하고, 회계용 매출 라인을 ERP(GL)로 일배치 전기.

▣ 2단계 — Swimlane (담당 / 시스템)

  • 주체 A (FRONT)   : 모바일 앱 결제 화면 / 사용자 UX
  • 주체 B (BACK)    : OMS + COOKIE_LEDGER + EPISODE_UNLOCK 등 운영 DB
  • 주체 C (SETTLE)  : 정산시스템 (Adjustment, Coupon, Promo, RS 계산)
  • 주체 D (ACCT)    : ERP / GL — 일배치 인터페이스 수신, 매출 전표 생성
  ※ 각 단계마다 외부주체(PG사 / 작가)가 인터페이스로 연결됨.

▣ 3단계 — 통제점(Control Point) — IT 감사 관점

  (A) ITAC — Interface Reconciliation
      PG사가 통보한 결제 금액(원장)과 COOKIE_LEDGER의 충전 금액 합계가 매일 자동 대사된다.
      차이 발생 시 PG_RECON_EXCEPTION 테이블에 적재되며, 결제플랫폼팀이 D+1 영업일 내
      해소해야 한다. 단, "한도 초과로 자동 종결되는 일정 임계값(±1만원) 미만 차이는
      자동 클리어"로 운영 중이라고 인터뷰에서 확인.

  (B) ITAC — Balance Validation
      회차 잠금해제 트랜잭션에서, 잔액 < 회차 단가일 경우 시스템이 차감을 차단(BLOCK)
      한다. 단, 프로모션 코드 적용 시 일시적으로 음수 잔액(-N)을 허용하는 예외 분기가
      있고, 이 음수 잔액이 일별 마감 시점에도 정산되지 않으면 매출 누락이 발생할 수
      있다고 정산팀 김 책임이 진술.

  (C) IPE — Calculation Accuracy (정산 리스트 — Key Report)
      월말 정산 리포트 생성 시, COUPON_USAGE / PROMO_RULE / FREE_PASS 차감 효과를
      모두 합산하여 NET_REVENUE를 산출한다. PROMO_RULE의 파라미터(예: '신작 1~3화 무료',
      '연재일 50% 쿠폰')는 정산팀이 GUI에서 직접 변경 가능하며, 변경 로그는 PROMO_RULE_HIST에
      자동 기록된다. 다만 변경에 대한 메이커-체커(2단 승인) 절차는 운영되지 않는다.

▣ 4단계 — 시각화에 필요한 추가 사실

  ⓐ 인터페이스 4종 — PG→COOKIE_LEDGER (실시간), COOKIE_LEDGER→REVENUE_LINE (분배치),
     REVENUE_LINE→GL (일배치), 정산결과→ERP_AP (월배치). 모든 인터페이스는
     IF_LOG_HEADER에 BatchID/RowCount/StartTS/EndTS가 기록되며, 실패 시
     IF_LOG_EXCEPTION으로 분기.
  ⓑ 환불 — 7일 이내 자동승인, 8일 이상은 CS 매니저 1단 승인. 단, "VIP 응대"라는 사유로
     콜센터장이 본인 ID로 직접 환불 처리한 사례가 분기당 12건 이상 확인.
  ⓒ 수기 분개 — 월말 매출 cut-off 조정과 PG 정산차이 조정 분개는 재무팀 박 차장이
     단독으로 기안·게시. CFO 사후 리뷰는 월말 마감회의에서 구두 진행.
  ⓓ SoD — "캠페인/프로모션 등록 권한"과 "프로모션 승인 권한"이 정산팀 시니어 3명에게
     동시 부여되어 있음을 GRC 분기리뷰에서 인지하였으나 미해소.
